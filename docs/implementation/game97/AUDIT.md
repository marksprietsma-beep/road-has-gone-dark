## CI diagnosis

Run 37956679299 (GAME-83) and 37956679358 (GAME-84) have successful native Windows counterparts and failing Linux rendering. Retrieved original `game83-qa-Linux` / `game84-qa-Linux` artifacts: GAME-84 `logs/input-render.txt` records `mouse selection exposes accepted-lead action`, followed by invalid access to `ui.action_buttons.leads` at capture-flow.gd:108. GAME-83's `logs/game84-and-foundations.txt` records Python TimeoutExpired after 1,800 seconds running that same script. The synthetic mouse position was outside the follow-focus scroll viewport; the missing UI transition abandoned the coroutine while SceneTree/rendering stayed alive. This is evidence of a test-driver error, not evidence that Windows or Linux gameplay should skip assertions.

GAME-96 already adds grab_focus before mouse input and pins the legacy authored journey diagnostic, while normal gameplay defaults to sandbox. GAME-97 retains both fixes; checks target existence and viewport containment; exits 1 immediately on a failed UI assertion; adds a 300-second failing watchdog covering otherwise-unbounded scene/signal waits; bounds that specific Python subprocess to 360 seconds. Two expected-failure probes exercise assertion and offscreen-input exit semantics without supplying their own quit. Existing positive visual journey remains enabled and must pass.

Legacy CI workflows referenced a different unverified Godot 4.7.2 download. GAME-97 aligns GAME-7/local-region/atlas/inspection checks with project 4.6.3 and official SHA-256 verification, matching the native exporter/helper contract.
