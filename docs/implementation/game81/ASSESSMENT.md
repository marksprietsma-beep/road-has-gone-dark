# GAME-81 engineering assessment

Verified GAME-80 draft #64 at `c661d31c41b255384de49a4db7be111b6a3abfc1`; remote head is unchanged. This new branch targets GAME-80 and leaves it untouched.

The existing origin transaction creates one campaign with three immutable skeleton adventurer IDs. GAME-7 already provides atomic same-slot replacement, restart recovery and strict origin validation. GAME-80 adds exact V1/V2 enrichment references; neither package nor its runtime manifest will be regenerated here. Party creation will extend those same three records, preserve their IDs, and never create a second campaign.

The GAME-78 character generator, original tables (30 occupations, staged family/training/motivation/keepsake choices), declarative contradictions, hierarchical seeds, Lexicon phonotactics and fact-bound Rant are already production modules. No research runtime promotion, new library or parallel character generator is necessary. A production adapter will consume the existing character generator and public GAME-80 hierarchy, choose locally compatible occupations with profile weighting, enforce default party diversity, retain structured facts, and render three complementary biography forms. Private generator fields and hidden world information are excluded from player output.

Culture is not ancestry. Canonical cultures contain IDs, name/base/type but no independently verifiable ancestry field or naming-base definitions. Fantasy words embedded in culture names are insufficient evidence; no ancestry will be inferred from names or base indices. An original data-driven eight-people pack will generate qualitative public presence independently at world/state/region/home levels. Stable culture IDs condition seeds, not a one-to-one race mapping. Geography is a soft preference, never a selection restriction. Every approved people remains available everywhere.

Add an immutable `peoples-v1` sidecar and a separate exact party runtime manifest. Existing V1/V2 pins and bytes remain unchanged. Missing-only creation runs under library locking; corrupt/pinned packages are refused. One existing Node helper carries all three generation services. Initial generation and deliberate rerolls run asynchronously, never every frame; candidates are validated before atomic campaign replacement and immediate reload validation. Generation/write/reload failure retains the campaign and same slot, with controlled retry. Edits preserve identities and sibling facts; reroll counters are saved.

Party schema V1 is additive to save version 1: status draft/ready, exact generation/people pins, three members referencing existing IDs/slots, editable name and edit marker, separate people/semantic-role IDs, origin/profile refs, public structured background and rendered biography. Missing party remains a valid historical save; explicit entry prepares it without destructive migration. Roles are V0 intent, not GAME-32 classes. A narrow main-menu resume-party action is required for crash/restart continuity; it does not enable the disabled Continue browser/game loop.

UI uses black/gold simple controls, three-slot overview, bounded details, people descriptions/commonness, name/role edits and deliberate background regeneration. Origin confirmation leads to party creation; ready stops at review/main menu, with expedition clearly deferred. No portrait generator is required.

Proof: both presets and five fresh offline worlds; exact repeated/order-independent presence, independent culture/people IDs; 1,000+ sequential backgrounds with diversity/duplicate/context metrics and 100 read examples. Explicit generation/corruption/invalid-ID/incomplete-party/write/reload failure tests; same-slot edit/restart/reroll invariance; legacy pins and fixture-byte regression checks. Real keyboard/mouse/Tab/arrows/Enter/Escape screenshots at 640/1280/2560. Native Windows and Linux full game/helper artifacts, notices and source-free empty-PATH lifecycle validation are mandatory; running jobs are never reported as passed.
