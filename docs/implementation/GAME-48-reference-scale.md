# GAME-48 — physical window reference, NOT actual game geography

The preceding GAME-46 diagnostic uses 16 horizontal and vertical **Azgaar map units**, while GAME-39 uses 64-unit global source tiles. Neither is a 30 km neighbourhood. Azgaar's pinned [coordinates generator](../../vendor/azgaar/src/generators/coordinates.ts) provides an *angular* geographic rectangle (`map.bounds.latN/latS/latT/lonW/lonE/lonT`) on its original `map.width/height` canvas. It does **not** establish the radius/circumference of the fictional world, gameplay walking speed, or exact small-scale relief.

## Two explicitly separate modes

- **Legacy source v1:** unchanged `buildLocalContext` with 16 source units and unchanged `local-source:v1:` immutable identifiers. All previous game area, source fixture, Town Forge seed, GameWorld and save contracts remain untouched.
- **Hypothetical reference v2:** opt-in `buildReferenceLocalContext`, *requires the caller to explicitly supply an assumed spherical world radius in kilometres* and a requested window span, e.g. **30 km at an assumed radius of 6371.0088 km** for an Earth-equivalent diagnostic. The local projection uses Azgaar's original equirectangular latitude and longitude bounds:

  `latitude = latN - y * latT / map.height`

  `km_per_source_unit_N/S = R * π/180 * latT/map.height`

  `km_per_source_unit_E/W = R * π/180 * lonT/map.width * cos(latitude)`

The resulting source window is rectangular in map units to make an *approximately square* assumed-distance neighbourhood at the selected burg's latitude. It is **not a physically accurate, canonical game scale**, especially across coasts, hills, poles or differing world-radius settings. Latitudes above 80 degrees are explicitly rejected to avoid false polar distortion. The context carries `physical_km: ASSUMED_NOT_CANON`, `reference_radius_km`, original angular coordinates and pixel-per-distance values. Cache identity is `local-source:v2:` and incorporates both parameters, never colliding with v1.

### Critical limitation: source resolution

In the test worlds (`latT=180°`, `height=800`), one Azgaar north/south pixel represents approximately **25 km only under that Earth-radius assumption**, and horizontal distance varies by latitude. A hypothetical 30 km window is typically ~1–2 source pixels, not 16. There may be **fewer than four Azgaar cell centres** inside it. The v2 data exposes `source_cell_centres_in_window` and `COARSE_MACRO_GEOGRAPHY_NO_WALKABLE_MICRO_DETAIL` so no engine system accidentally treats sparse Azgaar routes, river-cell chains, or polygon vertices as walkable neighbourhood geometry.

The eventual game requires a deliberate decision about in-world scale and a **source-constrained finer terrain model** to interpolate/infer local detail. Do not silently reinterpret Town Forge's earlier 1000 unit output as metres/kilometres, guarantee a walkable road from a single sparse Azgaar segment, or manufacture bridges, river mouths, accessible coastal ramps or sites. Source-road protective status remains unknown.

## Reproducible comparison

CI rebuilds both canonical worlds **byte-identically**, tests the isolated radius-reference maths against synthetic equal-angle and higher latitude worlds as well as original real burgs, and generates six original v1 neighbourhoods alongside six hypothetical 30 km v2 crops. It uploads pairs of SVGs and source JSONs, with assumption wording printed on each v2 image. Actual Godot local-region scenes continue using the unchanged v1 source context unless deliberately given a new, reviewed source-size policy.

For local inspection, in **PowerShell** after checking out the GAME-48 PR branch and installing vendor dependencies:

```powershell
cd C:\projects\road-has-gone-dark
node tests/regiongen/verify-reference-scale.mjs
node tools/regiongen/generate-reference-examples.mjs
```

The geography sidecar files in `tools/regiongen/.tmp` must already exist, generated by the documented `generate-azgaar.mjs --geometry-output` commands in the CI workflow. This remains a diagnostic; no Mark-local testing is required at this stage.
