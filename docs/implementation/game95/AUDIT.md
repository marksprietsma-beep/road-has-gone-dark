# GAME-95 audit and implementation plan

Base: delivered GAME-94 branch, documentation head `3c3343fd14282397c46932417f519df7b526ea40`, tested game `c4a5b7c7b55aaffff568e940c04ca9bf75eee61f`. Existing drafts #71/#72/#73 remain unmerged. The uploaded GAME-95 handoff is authoritative; no Linear access is needed. Pinned Godot/helper/build tooling is already available and verified from GAME-94; no setup configuration change is required.

## Audit before changes

- Party Creation uses one three-entry `ItemList` and Identity/Background tabs. The list already supports icons, so a small static paper doll can fit beside each name/people/calling without another editor or panel. GAME-32 records are prepared later, when the adventure begins. The existing pure `RulesRecords.preview_preparation` can preview that exact starting build on a local ready copy; it must never write mechanics into the draft campaign. Existing prepared records take precedence.
- `CombatArt.recipe` already supplies stable identity choices, equipment, compatible source layers, palettes and explicit anatomical fallbacks. Keep it as the single recipe authority. Share source-frame extraction with `CombatPawn` and compose static front-facing list icons from those same layers/textures, rather than defining a separate party appearance.
- Movement lasts 0.18 seconds per tile; attack/cast FPS and impacts are spread between catalog and pawn/controller/effect. Critically, `refresh` reparents the pawn at the committed destination, then `animate_committed` waits a frame before adding travel offset: that creates a destination flash. A second action can also cancel unfinished walking. AI waits a fixed 1.1 seconds, independent of route/impact/defeat duration.
- Pure tactical paths, attacks and AI already use `board.width/height` and authored spawns. Hardcoded view assumptions remain: `GridContainer.columns=8`, layout height `/6`, and animation pitch `/8` and `/6`. Tests also hardcode 48 cells and old positions.
- Battle validation pins the full `board` and encounter SHA to one unchanged `first-road-encounter.json`. Existing saved turns/results/hooks/history rely on the canonical `first-road-v1` encounter. Replacing that file would reject old campaigns and invalidate deterministic golden evidence.

## Minimal plan and critical tradeoffs

1. Extend the existing list with cached native LPC paper-doll icons. Preview the existing preparation calculation on a local copy, reuse actual prepared equipment when present, and test preview/combat recipe equality plus unchanged campaign bytes. Keep the current list navigation and compact tabs. Initial rendering exposed a Godot ItemList restriction: left-side icons ignore multiline captions. Use a small three-button roster component with the same selection/keyboard contract, existing GameUI styling and shared LPC thumbnails; this avoids joined text and oversized top-icon entries.
2. Introduce a small presentation-only pacing constants class. Install movement offset synchronously before a draw, use slower native frames/interpolation and timed impacts/projectiles/hit/down beats. Gate subsequent command buttons/AI only for a short computed presentation deadline; menu/escape can still leave a committed save. Never queue combat dice or make authority await animation. Timers have an explicit upper bound and resume clears visual waits.
3. Preserve the original 8×6 definition byte-for-byte. Add two registered immutable encounter layouts, 10×8 and 12×8, with the same canonical encounter identity and authored spawns/blocked cells. Only newly begun production fights explicitly select the 12×8 layout. Existing callers/replay fixtures can still request the legacy layout; validation recognizes each exact registered pin. No migration, second save writer or unrestricted generator is needed.
4. Separate authored terrain presentation data from mechanical board definitions so art edits do not invalidate saves. Render an original project-authored pixel roadside palette (track, verge, scrub, rocks/trees, ditch/milestone) beneath transparent tactical overlays using the existing grid Buttons. Blocked markings derive solely from authoritative blocked cells. No source-pack substitution or procedural layout is involved. Bind the scene caption to the existing site/hometown references where available; the map is an authored approach, not a fabricated world-generation result.
5. Remove fixed view dimensions and test all three sizes/resolutions. Keep compact sprite/HP readability, unchanged targeting and legal highlights. Run legacy frozen hashes/replays and real save/resume, deterministic new-layout command replays, all animation cases, rendered preview/full journey and native Windows packaging. Publish a stacked draft on #73 and a self-contained Windows review artifact.

A larger open layout necessarily changes possible paths and therefore may change AI command sequences/outcomes compared with the old board. Claim equivalence precisely: old saved layouts/replays retain exact board, initial RNG and results; timing/art do not alter any given layout's command/state/log/RNG. New layouts keep the rules and seed recipe, not a false promise of identical paths across different geometry. Engagement distance is kept near the original spawn spacing to avoid an empty walking phase.

Out of scope: ancestry/class mechanics, combat-rule redesign, unbounded map or dungeon generation, new world/origin flow, sound framework, final terrain families or merging any draft.
