# GAME-103 architecture and compatibility audit

Baseline: verified current main `a47f972` (GAME-101 PR #79 merged). Feature branch `feature/game-103-character-builder`. Godot 4.6.3, Node 24.19.0 and existing verified export templates/helper are available; reuse them without rebuilding dependencies.

GAME-32 already owns standard-array legality, typed prerequisites, skill budgets/rank caps, equipment effects, ordered advancement, immutable derived snapshots and resource validation. Its three base classes and Veil Adept are original authored content. The eight ancestry records grant neutral tags, not racial bonuses, and currently provide only one mechanical heritage each. One mechanical background exists; actual professions already drive GAME-101 companion interactions. Narrative roles are recommendations, not classes. No character-builder XP policy exists in the rules kernel; its advancement API deliberately receives trusted choices.

Reuse `RulesCharacter` create/preview_choices/preview_advancement/derive_character/available_advancement and `RulesRecords` campaign previews. Reuse PartyService's world guard, lock, recovery journal and GamePlaythroughStore: no second save writer. Preserve the exact v1 rules pack, original legacy party validation rules, sandbox versions, combat kernel, RNG, artwork and helper pins. Add a versioned player-authored party schema and creator draft namespace only to new or unfinished parties, so different source-backed personal origins and chosen professions can be validated without reinterpreting a legacy generated party. Confirmation is required for all three adventurers; previews are not committed gameplay statistics. Finalisation moves the drafts into the existing mechanics authority in one transaction. Ready legacy parties are never regenerated or forced through creation.

A shared data-driven build editor serves creation and advancement; a permanent sheet reads the saved record (active-battle runtime when fighting). Each starting character can choose name, ancestry/current compatible heritage, narrative role, source-world personal origin, compatible profession, ability allocation, mechanical class, skill ranks, eligible feat, equipment and granted preparations. Class/feat/skill/equipment choices come from the pinned registry. Current neutral heritage coverage is explicit; no new ancestry mechanics or imported D&D research content.

Add a small original campaign progression policy, separately pinned from unchanged GAME-32 definitions: cumulative journey XP threshold 20*(next_level-1)^2, starting level one free only during creation. Advancement at home requires real validated saved XP; never grant XP or levels from the production UI. Existing ordered class history is grandfathered. A reviewed advancement uses the existing kernel preview and retains spent/current resources. Prestige requirements are explained even while locked. Development fixtures alone may construct higher-level/prestige examples.

Accepted GAME-88 design and catalogue read from `research/game-88-dnd35-character-options` at `c09e5864245c1a7eef9ace7b71f79ac9928c04d8`. Ancestry, culture, origin, profession, class, role and lived history stay separate. Its hundreds of indexed options are research only; no names/prose/mechanics imported. The present eight peoples (including provisional Emberkin) are existing prototype options, not a final roster. GAME-104 owns wider original option content; GAME-105 owns future skill checks.

Modify the existing party-creation entry point to host the real builder, add permanent sheet entry points to expedition/combat, and correct class labels to read actual ordered mechanics rather than role recommendations. Add focused transaction/compatibility/advancement/full-journey tests, actual Godot renders at all requested sizes, native Windows/Linux packaging proof and a draft PR. No automatic merge.
